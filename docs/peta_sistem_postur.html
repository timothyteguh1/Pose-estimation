θ = arccos( (BA · BC) / (|BA| |BC|) ) × 180/π
shared src/features/joint_angles.py — fungsi calculate_angle()

11 sudut per frame (leher, bahu, siku, pinggul, lutut, pergelangan kaki — kiri & kanan). Titik dgn visibility < 0.6 membuat sudut itu saja jadi NaN (per-titik, bukan buang 1 frame utuh).

shared src/features/sliding_window.py
Eq. 4 — Cosine similarity (gerbang pola gerakan)bab 6.2.3
cos(θ) = (A · B) / (|A| |B|)
shared src/app/rep_counter.py

Opsional (mati secara default, min_pattern_similarity). Metode utama rep counting tetap deteksi puncak/lembah sudut — persis kalimat proposal bab 6.2.3.

4Penyimpangan dari proposal

menyimpang

Bab 6.4 proposal: "Pada sisi server dilakukan seluruh proses pengolahan data, mulai dari deteksi objek menggunakan YOLOv11, ekstraksi pose menggunakan MediaPipe, hingga klasifikasi postur menggunakan Random Forest."

Arsitektur baru memindahkan YOLO + MediaPipe ke client (langkah 2–4 di atas). Cuma klasifikasi RF + rep counting yang tetap di server.

Konsekuensi turunan: MediaPipe terpaksa pakai varian Tasks API (bukan Legacy Solutions) karena Legacy tidak punya versi browser sama sekali — bukan pilihan bebas.

Justifikasi: dibuktikan lewat pengujian jaringan nyata (tunnel) bahwa pendekatan server-side penuh gagal dipakai dari luar 1 jaringan yang sama — video lag berat, klasifikasi tidak bisa diandalkan. Ini harus ditulis eksplisit di Bab III sebagai keputusan desain yang disengaja dan berdasar bukti, bukan disembunyikan.

Syarat ruang lingkup lain (output a–e: bbox+skeleton, info klasifikasi, teks+suara peringatan, jumlah repetisi, ringkasan+screenshot; rep counting dari pola sudut; model pre-trained) tetap terpenuhi 100% di arsitektur baru — sudah dicek satu-satu di kode.

53 metode tambahan untuk generalisasi ke orang baru

baru testing — belum diterapkan ke kode produksi

Dilatih & diuji di script terpisah (scratchpad), belum masuk experimental_client_pipeline/models/. Kalau nanti diadopsi, otomatis berlaku untuk Live Camera dan Upload Video sekaligus (satu classifier yang sama dipakai keduanya).

5.1 Koordinat relatif rumus baru

coord_rel = (coord_mean − pusat_pinggul) / panjang_torso

66 kolom tambahan (33 landmark × sumbu x,y). Menghilangkan informasi posisi/ukuran orang di frame yang seharusnya tidak relevan untuk postur. Hanya menyentuh fitur koordinat (pendukung) — sudut sendi (fitur utama, Eq.1) sudah otomatis invarian terhadap posisi/skala dari sononya, tidak disentuh.

5.2 Mirror augmentation prosedur, bukan rumus

Tiap window data training digandakan versi cerminnya: landmark kiri↔kanan ditukar, koordinat x dibalik (x' = 1 − x). Kelas tidak berubah. Data training jadi 2× lipat.

5.3 Regularisasi Random Forest parameter, bukan rumus

min_samples_leaf: 1 (default sekarang, tidak pernah diset eksplisit) → 4. Memaksa pohon berhenti bercabang lebih awal supaya tidak menghafal detail 1 window/1 orang spesifik.
